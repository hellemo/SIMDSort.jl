Sorting

simdsort!(v::Vector{String}; rev=false, ntasks=1)
simdsort!(v::Vector{Symbol}; rev=false, ntasks=1)

Sort strings or symbols in the order of isless (bytewise, shorter first on a common prefix), through simdsortperm.

source
simdsort!(v; rev=false, ntasks=1)

Sort v in place in the order of isless (NaNs last, -0.0 before 0.0), or its reverse if rev. Vectors of Int32, Int64, UInt32, UInt64, Float32 and Float64 use the vectorized quicksort; anything else falls back to sort!.

With ntasks > 1, large subranges are sorted by up to ntasks concurrent tasks; ntasks = Threads.nthreads() uses all threads.

source
SIMDSort.simdsort — Function
simdsort(v; rev=false, ntasks=1)

Return a sorted copy of v; see simdsort!.

source
SIMDSort.simdsortperm — Function
simdsortperm(v; rev=false, ntasks=1) -> Vector{Int}

The permutation that sorts v stably (as sortperm(v; rev)), for vectors of Int32, Int64, UInt32, UInt64, Float32, Float64, String and Symbol. Positions and key bits are packed into UInt64s and sorted with the vectorized quicksort; other inputs fall back to sortperm.

Types of your own

SIMDSort.orderwords — Function
orderwords(x) -> NTuple{M,UInt64}

The order key of x as M big-endian 64-bit words (most significant first), compared lexicographically, for element types T with has_orderwords(T) == true. Package extensions define both (DoubleFloats, MultiFloats, Quadmath); simdsort! and simdsortperm then sort such vectors by their words.

source
SIMDSort.has_orderwords — Function
has_orderwords(T) -> Bool

Whether elements of type T define orderwords, so that simdsort! and simdsortperm sort vectors of them by their words. false unless a method is added for T.

SIMDSort.tuning_report — Function
SIMDSort.tuning_report(path = "simdsort-tuning-<host>.txt"; ntasks = Threads.nthreads(),
                       rounds = 5, sizelog = 24) -> path

Run a fixed set of instrumented sorts and write what is needed to tune SIMDSort for this machine to the text file path:

  • the machine: CPU model, threads, caches (Linux), the SIMD features found, and the vector width and lanes the kernels use;
  • per case (random 64- and 32-bit integers and floats, few distinct values, Int128, String sortperm): best and median wall time of rounds fresh inputs, with one task and with ntasks; for the primitive types with ntasks, also with each top level forced (parallel quicksort, sample-sort step), which is what the threshold rule use_distribution is fitted to;
  • the phase times and counters of the median run (as print_report).

Takes a minute or two with the defaults (2^sizelog keys for the primitive cases). Start Julia with all threads (julia -t auto); ntasks = 1 measures one thread only.

julia> using SIMDSort

julia> SIMDSort.tuning_report()
"simdsort-tuning-myhost.txt"
