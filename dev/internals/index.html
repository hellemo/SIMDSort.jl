SIMDSort.KeySource — Type

Key sources. Each key is a big-endian bit string; the interface:

  • keybits(ks, i, off, K): bits [off, off + K) of key i (K ≤ 63), zero past the end, complemented for reverse order;
  • keywidth(ks): the key length in bits, for fixed-width keys; or exhausted(ks, i, off): whether key i has no bits from off on;
  • length_tiebreak(ks, a, b): the order of keys whose bits are all equal (default 0; strings put the shorter first);
  • finish_ties!(ks, perm): the same for a run of equal keys (default: none).

SIMDSort.MappedKeys — Type
MappedKeys(), NativeKeys(), FloatKeys()

How the six primitive types are sorted (keyclass(T)): Int32, Int64 and UInt64 are mapped to signed keys (UInt64 is sorted as is with 512-bit vectors); UInt32 is sorted as is; Float32 and Float64 are sorted as floats. Each class has its own sort_primitive! method, which keeps its own (measured) order of the cheap checks for special inputs (counting, presorted, hash counting).

SIMDSort.bucket_of — Method
bucket_of(spl, x, Val(nb)) -> Int

Branch-free search: the number of splitters spl[1:nb-1] that are <= x (spl sorted, length nb; spl[nb] is never read). nb is a compile-time constant: the loop unrolls into conditional moves; with a run-time nb it compiled to branches, 8 mispredictions per key.

SIMDSort.choose_pivot — Method
choose_pivot(p, n, s, buf) -> (pivot, dup, s)

For ranges above BIGPIVOT_MINN keys: the exact median of basecase_max(T) keys loaded as vectors from pseudo-random offsets, sorted with the base-case network in buf. dup is set when at least 1/9 of the sample equals the pivot. Otherwise as choose_pivot(p, n, s).

SIMDSort.choose_pivot — Method

Median of the lane-wise medians of three of three vectors loaded at pseudo-random offsets. dup is set when at least N of the 9N sampled keys equal the pivot, which suggests a large block of equal keys. Needs n ≥ N; s is the generator state.

SIMDSort.counting_sort! — Method
counting_sort!(v, order, ntasks) -> Bool

If the integers in v span a range of at most COUNT_MAXRANGE values and fewer than length(v) ÷ 4, sort v in order by counting each value and writing the runs, and return true. Otherwise leave v unchanged and return false. Works on the original values, so no key map is needed.

A sample of 1024 keys rejects wide ranges and sets up a count table over the sample's range plus a margin. Keys outside it go to an overflow slot; if any do, the table is redone over the exact range from a min/max scan.

SIMDSort.finish_bucket! — Method
finish_bucket!(v, tv, a, e, f, rev, keys, idx)

Sort tv[a:e] stably by order words into v[a:e]: one SIMD sort of 64-bit keys (a window of the order words just below the bucket's common prefix, above the local position), then a full comparison within the rare runs of equal windows.

SIMDSort.halves_body — Method
halves_body(R, N)

Code for an R×N network (R = 32, more registers than AVX2 has) built from two R/2-row networks, which fit in the 16 registers, and a bitonic merge done half by half (docs/src/design.md §5):

  1. sort rows 0..R/2-1 (A) and rows R/2..R-1 (B) as R/2×N matrices; each comes back as N·R/2 sorted keys, register by register;
  2. compare A[i] with B[last - i] (register R/2-1-r of B, lanes reversed): the minima stay in A, the maxima go to B, register by register. Afterwards every key in A is ≤ every key in B, and both halves are bitonic;
  3. sort each half with the half-cleaners of a bitonic merge: register pairs at distances R/4, ..., 1, then lane pairs at distances N/2, ..., 1.

Steps 2 and 3 only ever need two (step 2) or R/2 (step 3) registers live, instead of all R, which avoids most register spills.

SIMDSort.partition! — Method
partition!(p, n, pivot, buf, Val(U), Val(PF)=Val(false)) -> m

Reorder the n ≥ 2U*N keys at p so that the first m are ≤ pivot and the rest are > pivot. buf must hold at least 2U*N + N keys. U vectors are processed per iteration. With PF, the keys PFDIST ahead of each read are prefetched.

Three-way version of partition!: afterwards the keys in [0, a) are below the pivot, those in [b, n) above it, and [a, b) holds the pivot value.

SIMDSort.ppartition! — Method
ppartition!(p, n, pivot, ntasks) -> m

Parallel version of partition!. Each of ntasks chunks is partitioned in place by its own task. Then the keys > pivot that ended up in [0, m) are swapped with the keys ≤ pivot in [m, n); both sets have the same size, X, and each task swaps an equal slice of them.

source
SIMDSort.pqsort! — Method
pqsort!(p, n, depth, s, ntasks, total, sem)

Like qsort!, but while a range is larger than the grain max(PAR_MIN, total ÷ (GRAIN_FACTOR * ntasks)) the smaller side of each partition is sorted by a new task. Ranges larger than PPART_MIN are partitioned with ppartition!, by as many tasks as their share ntasks * n / total. Waits for all tasks it started.

The caller holds a slot of sem (ntasks slots); pqsort! gives it back before waiting for its tasks, each of which takes its own.

SIMDSort.refine! — Function

SIMDSort.spawn_limited — Method
spawn_limited(f, sem) -> Task

At most ntasks tasks of one sort run at a time, as simdsort! promises. Julia's scheduler runs a spawned task on any of its threads, so without this ntasks = 2 in a 56-thread Julia used all 56 cores. A task takes a slot of the semaphore before it starts working; tasks waiting for a slot hold no thread.

SIMDSort.split! — Method
split!(p, n, pivot, dup, buf, partition) -> (a, b)

Partition around pivot. Returns (a, b): the keys in [0, a) are below the pivot (or equal to it if a == b), those in [b, n) above it, and those in [a, b) equal to it, so they are done. When dup is set (the sample suggests many keys equal to the pivot), one three-way pass splits off the equal block; otherwise partition(p, n, pivot) makes a two-way split and a == b.

SIMDSort.tuning_report — Function
SIMDSort.tuning_report(path = "simdsort-tuning-<host>.txt"; ntasks = Threads.nthreads(),
                       rounds = 5, sizelog = 24) -> path

Run a fixed set of instrumented sorts and write what is needed to tune SIMDSort for this machine to the text file path:

  • the machine: CPU model, threads, caches (Linux), the SIMD features found, and the vector width and lanes the kernels use;
  • per case (random 64- and 32-bit integers and floats, few distinct values, Int128, String sortperm): best and median wall time of rounds fresh inputs, with one task and with ntasks; for the primitive types with ntasks, also with each top level forced (parallel quicksort, sample-sort step), which is what the threshold rule use_distribution is fitted to;
  • the phase times and counters of the median run (as print_report).

Takes a minute or two with the defaults (2^sizelog keys for the primitive cases). Start Julia with all threads (julia -t auto); ntasks = 1 measures one thread only.

julia> using SIMDSort

julia> SIMDSort.tuning_report()
"simdsort-tuning-myhost.txt"
