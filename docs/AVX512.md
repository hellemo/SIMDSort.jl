# AVX-512 notes

SIMDQuickSort.jl was developed and measured on an AVX2 laptop (Intel Core Ultra 7
268V). This file lists what changes on an AVX-512 machine, what the code already
does about it, and how to measure the rest, e.g. on an NTNU Idun node.

## What changes on AVX-512, and what the code does

| Aspect | AVX2 (measured) | AVX-512 | In the code |
|---|---|---|---|
| Vector registers | 16 | 32 | The 32-row base-case networks are split into two 16-row halves only without AVX-512 (`sortnet`, `src/network.jl`). |
| 64-bit integer min/max | compare + two blends | native `vpminsq`/`vpmaxsq` (also on 256-bit vectors, AVX-512VL) | Int64 leaves are sorted as Float64 offsets (`leaf_sort!`, `src/sort.jl`) only without AVX-512. |
| Partition step | `vpartition`: permutation table + `vpermd` | same (SIMD.jl keeps the table for 2/4/8 lanes) | Unchanged. Native `vpcompress` (Bramas 2017) might be faster on recent cores: measured by `bench/avx512.jl part`. |
| Vector width | 256-bit (`lanes(T) = 32 ÷ sizeof(T)`) | 512-bit possible | Kept at 256 bits. 512-bit vectors would need the AVX-512 float min/max intrinsics in `vmin`/`vmax`, and re-tuning; some Intel parts clock down under 512-bit instructions. |
| Tuning constants | unroll 8, prefetch 512 keys ahead above 2 MB, 32-row base case | different caches (e.g. 1–2 MB L2) | Unchanged; worth re-measuring. |

The first two rows are decided when the code is compiled, from
`SIMD.Targets.has_feature` (host CPU, `-C native`). On AVX-512 they select code
paths that are tested on AVX2 as well: the single 32-row network, and the integer
networks.

## Running the measurements on Idun

On a node with AVX-512, for example in an interactive job (`srun --pty ...`)
with your usual account and partition:

```sh
lscpu | grep -o 'avx512[a-z]*' | sort -u        # expect avx512f, avx512vl, avx512dq, ...

# Sources next to each other (as in the development setup):
git clone git@github.com:hellemo/SIMDQuickSort.jl.git
git clone git@github.com:hellemo/ChapelSort.jl.git
git clone -b permute-compress git@github.com:hellemo/SIMD.jl.git

# C++ SIMD sorts for comparison, built for the node's CPU (-march=native,
# so x86-simd-sort and vqsort use AVX-512):
ChapelSort.jl/bench/simd/build.sh

cd SIMDQuickSort.jl
julia --project=bench -e 'using Pkg; Pkg.instantiate()'
julia --project=. -e 'using Pkg; Pkg.test()'               # correctness on AVX-512
julia -t 16 --project=bench bench/avx512.jl all              # all three measurements
julia -t 16 --project=bench bench/bench.jl 9                  # the full comparison
```

`bench/avx512.jl` prints:

1. **Partition kernel** (ns/key): our permutation-table step against a Bramas-style
   step with native compress. If compress wins clearly, `part1` should use it on
   AVX-512.
2. **32-row network** (ns per call): one network against two halves. With 32
   registers the single network should win. If not, remove the AVX-512 condition
   in `sortnet`.
3. **Full sorts** against x86-simd-sort and vqsort, both with their AVX-512 code.
   On AVX-512, x86-simd-sort is expected to be much faster than on AVX2.
